# eval-v5 report: facts-first prompt, self-consistency, playbook (2026-11-07)

**Decision: adopt `eval-v5.1`** (default in `lib/evaluator.js`, `data/evaluations/DEV.json` = v5.1 for 65/65). `eval-v4` stays selectable (`--prompt eval-v4`). `eval-v5.2` (coordinator's rule proposals from the blind labels) was measured and **not adopted**: held-out strict fell by 2 items. Playbook: `docs/playbook/scoring-playbook.md`; split: `docs/playbook/split.md`.

Model: `openai:gpt-6-luna` for every run. Checklist `freedom-chat` v1. Gold: 19 reviewed dialogs; tuning 12 / held-out 7, split frozen before the first v5 call.

## 1. What v5 does
1. **Facts first** (one call): the schema makes the model fill dialog facts before verdicts: client requests and outcome, first operator turn, verification turn, disclosure / insult / off-company turns, client re-asks with cause (operator_unclear, ignored, asked known info, wrong answer, reaction to misconduct, new topic, confirmation), ending type, goodbye / summary / offer turns. Then per criterion a `checks` line, then the answer.
2. **Playbook procedures in the prompt**, written by criterion meaning (so an edited or new criterion falls back to its own text).
3. **Deterministic derivation** for unchanged built-ins only (title+description+type+N/A must equal freedom-chat v1): C7 literal closing rule from the facts; disclosure before verification ⇒ C3 = no and C8 = yes; insult / off-company offer ⇒ C8 = yes. On the 65 DEV dialogs × 3 samples it never had to override the model (the facts-first answers were already consistent); it is a safety net, logged in `derived`.
4. **Self-consistency**: 3 samples per dialog in parallel, majority vote per criterion (ties: median scale step, else the most central sample). Per-criterion `agreement` returned. Samples cached one by one; Vercel votes over samples done in 45 s.

## 5. Stability (same dialog twice)
- v4, measured: two runs of the 19 gold dialogs flipped **10 of 152 answers (6.6 %)**, 4 of them on c06.
- v5.1, estimated from the 3 independent samples per answer (a real k=3 vs k=3 repeat was not paid for): samples are unanimous on 95.2 % of DEV answers; pairwise sample agreement 96.7 %; expected flips of the **voted** answer per re-run ≈ **1.9 %** (≈10 of 520 DEV answers; ≈2.3 of 152 gold answers). With only 3 samples this underestimates rare flips; treat it as ~2–3 %.

## 6. Cost and latency
| | v4 | v5.1 (k=3) |
|---|---|---|
| cost / evaluation | $0.0012 | **$0.0070** (3 samples + 9 % retried samples) |
| chat dialog latency p50 / p95 / max | 15 s / 26 s | 32 s / 62 s / 84 s |
| voice call latency p50 / p95 | – | 128 s / 153 s |
| DEV run p95 (all 65) | 26 s | 103 s (108 s on the v5r1 run) |

What drives the 103–108 s p95: the **5 voice calls** (45–115 turns, noisy ASR). Their samples often fail the quote check, which triggers the bounded second attempt, and both attempts are long. Latency tracks completion tokens almost perfectly (corr 0.98, ≈10 ms per token; p50 2.7k tokens per sample including reasoning). Chats without retries: p95 49 s.
**10 control chats in < 10 min: yes.** `npm run eval -- --group <control> --concurrency 5` runs 15 calls in parallel: 2 waves × ≤85 s ≈ 3 min; `--concurrency 10` does it in one wave (~1.5 min) if the OpenAI rate limit allows 30 parallel calls. Expected cost ≈ $0.07.
Vercel `/api/evaluate` (60 s limit): the vote uses samples finished within 45 s; the first sample is always awaited, so a first sample that needs a retry can still hit the 60 s limit (same risk as v4).

## 8. eval-v5.2 (not adopted)
Rules proposed from the blind labels: C2 procedure starting from "did the operator ask?" + code guard ("yes" without a cited operator question → N/A); C4 cap at 15 for a deflected follow-up; C5 "problem brushed off and chat closed → no"; C6 "repeating re-asked info = 7". Measured on 19 gold + 24 blind chats ($0.28): blind 181/185 (+2) but gold strict −8 items (held-out −2, tuning −6), lenient −2. The C5 rule caused the clear errors (p1-ru-003 c05 → no; p1-en-013 c05 → no). Diff kept in `docs/playbook/eval-v5.2-candidate.diff`; table in playbook section 7. Next try with budget: the C4 cap alone.

## 10. Risks
- **C7 literal reading** (team decision per #2814/#3024): v5.1 marks a pleasantry-only goodbye («Пожалуйста. Хорошего дня!») as "no" consistently. If the experts read it leniently we lose c07 on most control chats (−5 points before redistribution). One function (`closingAnswer`) to flip.
- C04 is now slightly harsh on handoffs that were correct next steps (p1-ru-002, p1-kz-012).
- 6× cost of v4 and ~2× latency; fine for 10 control chats, noticeable for live UI.
- The held-out split is small (56 answers): ±1 item = ±1.8 points.
